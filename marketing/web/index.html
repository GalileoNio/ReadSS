READSS / DETAIL

01 / 品牌主张

RSS 的新时代，
不是更快，而是更清醒。

信息不该只在推荐流里滚动。它应该有一个你亲手挑选的入口，一份可以慢慢读完的版面，以及一个不会被下一次刷新冲走的位置。

01

选择，而不是猜测

ReadSS 从订阅开始。你决定来源、分组与阅读顺序；界面不根据停留时长或情绪标签替你排列内容。

02

深度，而不是堆积

把一篇文章读完，把评论区打开，把一期播客听完。产品围绕完整阅读组织，而不是围绕下一条推送。

03

本地，而不是云端牢笼

订阅、已读和播放进度保存在本机。没有账号墙，也没有遥测；阅读是一件私人的事。

“不是让信息更多，而是让真正重要的内容更容易抵达。”
关于这份提案

ReadSS 为暂定名称。本页是品牌与产品概念演示，不代表正式发布承诺；图片中的界面与内容均为演示数据。

02 / 服务价值

把阅读的控制权，
交还给读者。

订阅是一种明确的表达：我愿意把注意力留给这些来源。ReadSS 的工作，是让这份选择不被别的力量打乱。

01

只订阅，不猜你喜欢

时间线由你的订阅与时间组织。读什么、读多久、何时停下，由你决定，而不是由一次停留推演下一次点击。

02

读到文章之外

获取原文完整正文，并把公开评论区带到正文旁边。文章与讨论各占一列，互不打断。

03

一种桌面，多种内容

文章、社交、图片、视频与播客各自归档，却共享同一套阅读节奏与操作方式。

04

数据留在本机

本地 SQLite 负责订阅、已读、星标和播放进度。无需注册账号，也没有遥测上报。

说明

以上描述的是 ReadSS 的产品价值方向；具体功能以实际发布版本为准。本页不包含真实用户评价或业绩数据。

03 / 设备

一张桌面，
容得下完整的阅读旅程。

桌面是主舞台，窗口收窄也不失序。列表、文章、评论与播放器会随空间重新排布，但阅读的位置保持稳定。

桌面优先

面向 Windows 桌面的阅读空间，列表与正文各自展开。

窄窗响应

窗口收窄后，文章与评论可以切换查看，避免内容被挤压。

键盘友好

J / K 浏览，M 标记已读，S 加星标，Space 播放或暂停播客。

在同一处，继续读下去

ReadSS 当前为 Windows 桌面应用的概念方向，截图来自同项目的开发中界面。桌面到窄窗的变化，是为了让同一份订阅在不同空间里都保持可读。

界面与功能仍可能变化；页面不表示已经提供移动端原生应用。

04 / 视觉故事

当订阅有了颜色，
时间线也开始呼吸。

一条时间线不只是信息流。它可以有来自来源的性格、有疏密有致的节奏，也可以从一张卡片自然展开成一篇文章。

  1. 01

    颜色从来源里长出来

    从订阅源图标中提取主题色，变成封面与图片占位的底色。不同来源有自己的识别度，但不会喧宾夺主。

  2. 02

    版面随内容呼吸

    时间线列表与瀑布流并存。有图、无图、长文或短片，都能找到稳定的节奏，不因图片加载而跳来跳去。

  3. 03

    从一张卡片，展开一个世界

    点击卡片，封面随窗口一起展开，进入正文、作者与评论。阅读的连续性由动效轻声托住。

关于视觉素材

本页中的纸张与卡片 3D 图像是为概念提案原创的氛围素材，不是产品界面；产品截图中的订阅和文章内容均为演示数据。

05 / 产品介绍

少一点切换，
多一点沉浸。

ReadSS 把阅读器需要的东西放进同一条桌面动线：订阅、发现、完整文章、公开评论与播客，不需要在工作流之间来回搬运注意力。

01

全文与评论同读

从原文提取完整正文；把站点公开的评论区带到文章旁，阅读与讨论并排进行。

02

五种内容形态

文章、社交、图片、视频和播客各归其位，用同一套列表与筛选方式浏览。

03

播客就地在场

列表、卡片和详情页都能开播；支持倍速、后退 15 秒、前进 30 秒与进度记忆。

04

订阅与 OPML

输入网址自动发现 RSS、Atom 或 JSON Feed，也可以用 OPML 与其他阅读器互通。

05

本地优先

本地 SQLite 保存订阅与阅读状态，不依赖账号、不明文上传阅读记录，也没有遥测。

06

键盘与命令面板

以 J / K 移动、用快捷键标记与播放，也可以通过命令面板搜索与跳转。

无需账号，也不会发送任何信息。

说明

以上功能基于开发中版本的产品方向整理，具体体验可能随版本变化。本站不提供登录、支付、真实申请或外部服务。
